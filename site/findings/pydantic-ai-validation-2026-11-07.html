pydantic/pydantic-ai · 2026-11-07

Typed output, tested beyond the happy path.

Pydantic AI returned a declared City model for valid test output. Deliberately invalid output triggered the library’s output-retry error. Both checks ran against the actual library using its local TestModel backend.

Automatic selection from a saved batch · Docker execution · estimated token cost $0.364

What the experiment established

  • Valid test output returned an actual City model instance.
  • An integer in a string field triggered UnexpectedModelBehavior after the output retry limit.

Recorded output

OK name='a' country='a' <class '__main__.City'>

RAISED UnexpectedModelBehavior Exceeded maximum output retries (1)

Scope of this finding

  • Only the synchronous local TestModel backend was exercised. Real LLM providers, async execution, and streaming were not tested.
  • The negative test prints its exception rather than asserting its exact type. Its recorded stdout supplies the observed result.
  • No separate type-coercion case or full repository language audit was performed. No explicit source commit hash was captured.

Presentation review: The original automated report uses stronger wording about pure Python and coercion. This reviewed presentation narrows the conclusion to the two observed validation behaviors; the original remains unedited in the evidence below.

Original automated report and tool trace — unedited

Stored verdict: supported · 2026-11-07T20:40:00.933706+00:00

Yes: pydantic-ai's agent loop genuinely validates model output against the declared output_type, coercing conforming responses into real class instances and catching/retrying non-conforming ones before ultimately raising an error. This was confirmed by directly running the agent with a fake test model under both valid and invalid output conditions.

Evidence ledger

inspected · Repository is pure Python, MIT-licensed, and small enough to clone, making the claim directly testable in the sandbox.

sandbox_run(agent run_sync with City output_type)

observed · When the test model was forced to emit output violating the schema (country set to int 123 instead of str), pydantic-ai caught the mismatch internally, performed an automatic output retry, and ultimately raised UnexpectedModelBehavior: Exceeded maximum output retries (1), showing validation is applied inside the agent loop itself.

Recorded limitations

  • Only the synchronous local TestModel fake backend was tested, not a real LLM provider's wire format or async streaming output.
  • The internal retry/validation source code was not inspected line-by-line; behavior was inferred from black-box exception output.
  • Nested or union output_type edge cases were not tested.
